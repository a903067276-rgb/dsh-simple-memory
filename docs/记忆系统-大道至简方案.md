## 一、为什么转向：重大发现

翻了 DSH 源码（`dsh-agent-instructions` 插件），它的"指令文件自动加载"机制是这样的：

- 每次开会话，从 **全局**（`~/.dsh/AGENTS.md`）→ **项目根**（找 `.git` 标记）→ **当前目录**，逐层发现"指令文件"
- 默认只认 `AGENTS.md` / `CLAUDE.md` 两个文件名，**但候选名单可配置**（`instructionFileCandidates`，加一个名字即可，如 `MEMORY.md`）
- 所有文件共享 **64KB 预算**（`maxBytes: 65536`），塞不下时**从最宽泛的开始砍**（全局先砍，项目后砍），最具体的最后截断
- 文件改动自动重渲染，会话恢复兼容
- 挂载位置：agent preset 的一行（当前会话在 `~/.dsh/.agent-presets/standard-flash/agent.cordis.yml` 第 41~44 行）
- **注意：改 preset 配置只对新会话生效**（当前会话已加载完）

### 旧方案 vs 新方案对照

| 旧设计里的活（要写代码） | 大道至简后的答案 |
|---|---|
| 插件实现自动加载（L0/L1 分层） | 现成机制，白拿（agent-instructions） |
| 超 200 行拆分、"只加载精华" | 64KB 预算自动截断保护 |
| 跨项目搜索 | agent 自带 grep/glob 工具 |
| 升级机制（项目经验→全局规则） | 暂存池 + 确认出池（见三·六·2） |
| agent 写记忆 | 强制格式写入工具（见三·六·3） |
| 记忆面板、到点提醒 | 记忆按钮（插件，v1） |

## 三、已拍板的决策（总纲）

1. **AGENTS.md 是纯规则文档**：只放"路径 + 几句话能确定的规则"，琐碎经验一律进 memory。不堆内容。
2. **统一判断标准（唯一标准）**：*"这条 AI 下次干活没带着，会出问题吗？"*
   - 会 → 便利贴（AGENTS.md，人确认后才贴）
   - 不会 → 仓库（memory/，路径可达即可）
   - "重要/琐碎"两个词从此不用纠结，只问这一句。
3. **全局记忆分活跃区与冷区（不搞中间层）**：默认带的（用户画像、工作法）留在全局 AGENTS.md——它们本来就符合"缺了会出事"；升级出来的进 `common/`（活跃）；参考资料与归档各占冷区（`references/` 外部资料、厚资料；`archive/` 被遗忘移出的旧记忆）。**不搞"半全局"中间层**：跨项目的东西直接升级成全局。
4. **升级是一个动作，不是一类东西**：项目 memory → **暂存池** → 用户点头 → 提炼抽象 → 写入全局 `common/`（详见三·六·2）。不做专门的"定期整理"。
5. **触发机制**：记忆按钮（用户随时一键触发规范记忆流程）+ systemPrompt 约定（模型每轮看到判断标准，自然有"要不要记"的意识）（详见三·六）。**整理与否永远交给人判断**。
6. **写记忆协议**：提议（按钮/约定）→ 人确认 → 强制格式写入 → **贴产出物供核对**（详见三·六·3）。写前必须确认（防错记忆污染）。
7. **活文档，不按日期堆文件**：memory/ 里的 md 覆盖式维护、沉淀结论（活页本模型），日期写在条目里。不要 `2026-08-18.md` 按天堆——堆多了全是噪音，AI 检索靠关键词不靠日期。
8. **遗忘机制**：归档软删除（`archive/`，仍在硬盘可翻旧账）+ 触顶治理（详见三·九）。
9. **"忆"的保证 = 开局注入索引（插件）**：会话开场把活跃区文件名清单塞进上下文（详见三·六·1），文件名即索引。

## 三·五、记忆的载体形态

**plan 文档 / 决策记录 = 记忆的天然形态**。本文档自己就是活例子：它是两场讨论的产出，本质就是一条记忆（决策+为什么+待办），只是出生在 plan 文档的外壳里。

- 记忆内容不用发明新格式：**决策记录（讨论→沉淀→确认）就是标准记忆条目**
- **存放分家、检索统一**：docs/ 放正式文档（给人看），memory/ 放工作记忆（给下次干活的 AI/自己）；**位置写错了可搬，但搬不搬不影响找得到**——检索同时覆盖 docs/ 和 memory/（详见三·八）
- 因此本文档留在 docs/ 即可，不需要搬进 memory/

## 三·六、插件边界（2026-08-18 定）

**纯约定会漏的地方是"记/忆"的入口 → 插件只管入口，存储仍零代码。插件共三件事：**

1. **忆的入口：开局注入记忆索引**（替代"约定 glob"，详见三·六·1）
   - 会话开始时把活跃区文件名清单塞进上下文："本项目有：部署流程、踩坑-端口占用；全局有：xxx"
   - 只注入**文件名索引**（不注内容、不占 AGENTS.md 预算、可跨项目聚合），内容仍按需读
2. **记的入口：systemPrompt 约定（软）+ 记忆按钮（硬，100% 走规范流程）**
   - **软**：记忆规范写进 systemPrompt 后，模型每轮都能看到"判断标准"，自然有"要不要记"的意识（**不做"每轮自检"插件——语义判断代码做不了，调模型又花钱**）
   - **硬**：输入工具行"记忆"小按钮（conversation.input.left，按插件同步规范 UI 规矩做）——**按钮的价值 = 100% 触发规范记忆流程**：点击后注入一条固定格式的"记忆流程指令"（见下），agent 严格照做，不自由发挥、不遗漏步骤
   - **记忆流程指令（固定模板）**：`现在执行记忆流程（按记忆规范）：① 回顾本轮对话，列出值得记的内容（决策/踩坑/新约定/偏好）② 逐条提议，等用户确认 ③ 确认后走 memory-write 工具写入 ④ 贴出产出物 ⑤ 顺手 git commit`
   - 按钮实现候选（开发时验证）：A 往输入框塞指令文本（plan-switch 同款已验证）/ B RPC 到 host 注入消息触发 agent 轮次（接口待验证）
   - 取舍：宁可漏、不可烦——模型漏判后果轻，你随时按钮补

**边界原则**：插件只管"开场递索引、按钮触发规范流程、写入管格式"，其他（存储、搜索、升级、遗忘、整理）全交给文件和约定。

**范围承诺（2026-08-18 定）**：当前只做**检索式记忆**（关键时刻"想得起"：索引触发 → 读全文 → 恢复上下文）。**自动联想式记忆明确不做**（没人触发时自己浮现，依赖模型原生能力，外置系统做不到），等检索式成熟后再议。

## 三·六·1、索引注入形态（2026-08-18 定）

**v1：纯文件名清单 + 分类分组展示（零维护）**
- 注入 = 文件名清单（自动 glob，**只收 `*.md`**），按分类前缀分组展示（`踩坑类：… / 流程类：…`）
- **不加摘要**（B 方案后置）：跑一段时间若出现"光看文件名判断不了相关性"的实例，再升级——AI 收尾时顺手维护摘要或讲究文件名
- **注入范围三段分开展示**：项目 `memory/` + 项目 `docs/`（检索不分家）+ 全局 `common/`；冷区（`references/`、`archive/`）不注入
- **注入位置**：系统提示（每次会话开场必有）；具体 API 留开发阶段查（host systemPrompt 服务）
- **注入时机**：**新会话开场注入一次**；长会话中途不重复注入（刚写的记忆 agent 自己就在上下文）；**检索永远现场搜文件系统**（实时、不过期），索引过期影响极小；写入完成给"写入回执"（#5 产出物），索引等下次新会话再生成

## 三·六·2、升格机制：暂存池（staging pool，2026-08-18 定）

**把"升格"从当场决策变成低摩擦捞取 + 批量整理。**

```
【入池】AI 按标准发现够格经验（跨项目 / 抽象后成立 / 影响干活）
        → 写进全局暂存池 staging.md（低摩擦，无需当场确认）
【提醒】池子非空 → 收尾提醒时顺带问："池子里有 N 条，要不要整理？"
        不整 → 留着，下次再问（不打扰）
【出池】你点头 → AI 提炼抽象 → 写入 common/ → 池子条目删除
【治理】池子条目 >10 或超 2KB → 提醒升级为"强烈建议整理"
```

**细节**：
- 池子位置：全局 `~/Documents/DSH/memory/staging.md`（待处理区，不属于活跃区/冷区任何目录）；条目带来源（日期 + 项目）
- **入池低摩擦的原因**：池子内容来自已确认过的项目记忆，只是"提炼升格"待确认；确认发生在出池
- 与收尾提醒合并：一句"有没有值得记的？池子里还有 N 条待整理"
- **条目保留判定依据**（"为什么够格"一行，整理时一眼看出当初为何捞它）：
  `- 日期 [来源：项目] 经验：xxx 依据：跨项目（另见 xxx 同坑）+ 抽象后成立`

## 三·七、记忆规范（草案，定稿后写入全局 AGENTS.md）

> 状态：草案。落地时定稿，作为全局 AGENTS.md"记忆规范"段落的正文。

1. **记忆位置**：项目经验记 `<项目>/memory/`；全局通用经验记全局记忆根目录（默认 `~/Documents/DSH/memory/`，**以插件配置为准**）
2. **判断是否值得记**：这条以后干活没带着，会不会出问题？会 → 记；不会 → 不记
3. **文件名**：`分类-主题.md`（格式硬规矩）；分类前缀开放自造，内置起步五个：`踩坑-` / `流程-` / `决策-` / `偏好-` / `背景-`
4. **一条记录 = 骨架固定 + 内容自由**：骨架 = 日期 + 结论 + 来龙去脉（踩坑类写"怎么踩的、怎么绕的"）；**具体表达自由**，不强制顺序/措辞（AI 收尾时可帮忙补结构，不要求用户写时守模板）
5. **写入前必须经用户确认**；触发入口：记忆按钮（一键走规范流程）或模型按判断标准主动提醒；写后贴产出物
6. **按需读取**：相关记忆读全文，不要整目录灌进上下文；**检索顺序先活跃后冷区**
7. **跨平台写法**：遵循 `plugin-dev/docs/插件同步规范.md`"开发风格铁律·跨平台写法"（路径 join()、主目录 homedir()、记忆根目录为配置项、内容不写绝对路径）
8. **操作透明**：任何记忆操作（记/升格/遗忘/整理/删除）必须**口头告知用户"正在做什么、做了什么"**，零静默操作；写入类操作附产出物；读/检索是常态行为，无需报告
9. **升格走暂存池**：发现可跨项目复用的经验 → 写进全局 `staging.md`（带来源与依据）→ 池子非空时提醒 → 用户点头才提炼入 `common/`（详见三·六·2）
10. **单文件 ≤ 2KB（约 50 行）**，超了拆姊妹文件；**活跃索引 ≤ 200 条目**，触顶走治理（详见三·九）

## 三·八、目录层级与命名规范（2026-08-18 定稿）

```
【全局】~/Documents/DSH/memory/          ← 路径是配置项，可换平台
├── README.md                ← 本目录说明（给人 + 非 DSH 工具看）
├── staging.md               ← 升格暂存池
├── common/                  ← 通用经验（活跃区）[英文目录名]
├── references/              ← 参考资料（外部资料、厚资料、原始记录，冷区）[英文目录名]
└── archive/                 ← 归档（被遗忘移出的旧记忆，冷区）[英文目录名]

【项目级】<项目>/memory/               ← 相对项目根，天然跨平台
├── 分类-主题.md            ← 活跃记忆（平铺）
└── archive/                ← 项目级归档（冷区）
```

**结构规则**：
- **一套规则两个层级**：全局 = 活跃 `common/` + 冷区 `references/` + `archive/` + `staging.md`；项目级 = 活跃平铺 + `archive/`（**不设 references/：项目级参考资料天然住 docs/，检索已统一覆盖，无需冗余**）
- `archive/` 保留的理由：软删除 = 永不真删；非 git 项目里直接删就找不回
- **目录名全英文**（提高兼容性）：`common/`、`references/`、`archive/`、`memory/`；**文件名不限制中英文**（`踩坑-端口占用.md`、`troubleshooting-port.md` 均可）
- **活跃区 vs 冷区**：`common/` = 活跃（注入索引）；`references/` + `archive/` = 冷区（不注入索引，命中搜索才读）；**归档 = 曾经的活跃记忆被遗忘移出；参考资料 = 本来就不进活跃区**，两个概念分开

**git 管理（条件约定）**：
- 全局记忆目录 `~/Documents/DSH/memory/` 开独立 git（防丢可回滚，agent 顺手提交）；用户环境没有 git 则裸目录，不强制
- **项目级 `memory/` 用独立嵌套 git，绝不与开发 git 混用**：项目 `.gitignore` 加 `memory/`（发布隔离，记忆永不进公开仓库），memory/ 自己 `git init`（版本独立，提交互不干扰）
- 记忆的 git 一律不推远端（纯本地资产）
- **提交细则**：**每次记忆操作（记/升格/遗忘/整理/删除）完成后立即 commit**，不攒批（提交粒度细 = 回滚点精确，能精确退到"这次操作之前"）；agent 代劳，操作贴完产出物后顺手 commit
- **commit 固定格式**：`mem: <操作> <对象>`，如 `mem: 记 踩坑-端口占用`、`mem: 升格 xxx`、`mem: 遗忘 xxx`、`mem: 整理 xxx`、`mem: 删除 xxx`
- **回滚是这套 git 的存在理由**：写错 `git checkout`、误删 `git restore`、整理改坏退到操作前 commit
- **`~/.dsh/AGENTS.md` 不建 git（太底层侵入），由 agent 顺手备份进全局记忆 git**（如 `~/Documents/DSH/memory/AGENTS.bak.md`，提交记忆时同步）；配置文件仅 5KB、每次会话都加载、改坏立即暴露，无需独立版本管理

**命名规范 v2（分类开放）**：
- **格式是硬规矩**：`分类-主题.md`（决定索引与检索，不许自由发挥）
- **分类前缀是开放的**：内置五个默认分类（`踩坑-` / `流程-` / `决策-` / `偏好-` / `背景-`），用户可自造（`灵感-xxx.md`），**不需要申请、不需要登记**；内置五个是"起步菜单"，不是"允许列表"
- **识别三层（不需要特殊符号）**：① 目录位置（记忆只在 memory/、common/、references/、archive/）② 命名格式（分类前缀是锚点，主题中英文随便混）③ 内容首行固定 `## 日期 分类-主题` 兜底。**不引入识别符号**——AI 认结构不认语言
- **日期进内容不进文件名**：活文档覆盖式维护，同主题更新改原文件，不按天堆文件
- **文件 = 主题（基本规则）**：换主题就换文件（`分类-新主题.md`），**跨主题内容绝不混进已有文件**；同主题内容未满 2KB → 更新改原文件；满了 → 拆姊妹文件（`分类-主题-补充.md`），原文件顶部加一行指引（"xxx 细节见 分类-主题-补充.md"）防散落丢失
- **目录级 vs 文件名级分类**：全局目录（common/references/archive）管"跨不跨项目"（粗），文件名前缀管"是什么类"（细），两层不冲突
- **docs/ 与 memory/ 分家（存放）但统一检索**：
  - docs/ = 正式文档（给人看：README、install、对外说明）；memory/ = 工作记忆（给下次干活的 AI/自己：决策、踩坑、偏好）
  - 判断规则：**"这篇是给人看的说明"→ docs/；"这篇是给下次干活的经验"→ memory/**，写时问一次
  - **检索不分家**：插件开局注入的索引、AI 按需搜索，**同时覆盖 docs/ 和 memory/**（不然 docs/ 里的方案与坑"看不见"）
  - 位置写错了可搬，但搬不搬不影响找得到（检索统一覆盖）

## 三·九、记忆质量上限与触顶治理（2026-08-18 定）

**模型"记得住"的经验值（flash 实测经验，设计参数由此推导）**：
- 单个文件舒适区 ≤ 2KB（约 50 行中文），5~10KB 打折，20KB+ 明显丢
- 同时展开 3~5 个小文件舒适，8~10 个打折，十几个以上丢细节
- 开头结尾记得最好，中间易丢（lost in the middle）

**硬数字（写进规范）**：
- **单条记忆文件 ≤ 2KB（50 行）**，超了拆姊妹文件
- **活跃索引 ≤ 200 条目**（几十个文件名仅几百 token，零压力；200 是治理触发线）

**触顶治理规则（超 200 或用户说"该整理了"时触发，动作全要人确认）**：
1. **整合**：主题相近的合并（`踩坑-端口A.md`+`踩坑-端口B.md` → `踩坑-端口占用.md`）
2. **遗忘**：过期/完成项目的经验移入 `archive/`——**还在硬盘，只是退出活跃索引**（遗忘 ≠ 删除）
3. **升级**：项目经验升全局（经暂存池，项目侧可删，一减一增）
4. **删除**：确认没价值的才真删（git 可找回）

**索引 = 活跃区，不是全量枚举**：插件注入只覆盖 active 部分（项目 memory/ + docs/ + 全局 common/）；冷区（`references/`、`archive/`）不主动注入，命中搜索才读。上下文永远清爽，硬盘永远完整（"预算截断是天然遗忘"的同一哲学）。

## 三·十、子目录开合规则（方案 D，2026-08-18 已确认）

**核心洞察：索引 = 虚拟目录**。找东西靠索引不靠层级，物理子目录的唯一价值是让索引清单变短。

- **固定结构目录是例外**：全局 `references/`、两级 `archive/` 是系统的固定组成部分，不属于"内容子目录"；本规则只管**活跃内容区**（永远平铺）
- **v1 活跃区永远平铺**，不预设内容子目录（排除按分类建——与文件名前缀重复）
- **开子目录只有两条路**：① 触发信号出现 ② 用户主动要求；AI 不会自己没事提议
- **触发信号**（任一即讨论开子目录）：① `memory/` 文件数 > 20 ② 某领域文件成群（≥6 个同主题）③ 用户说"乱了" ④ 软信号：命名撞车、检索老找错
- **开了的规矩**：AI 提议怎么分 → 用户确认 → git mv 迁移 → 文件名前缀不动 → 子目录名英文
- **按领域开不按分类开**（分类已有前缀管，领域才是平铺缺的维度）
- **保险：检索永远递归**（`memory/**/*.md`），物理层级怎么长都不影响索引与搜索

## 三·十一、机械介入技术设计（DSH 官方接口，2026-08-18 定）

> 全部使用 DSH 官方文档化接口（插件同步规范铁律：不 hack 内部）。以下接口已用 cordis_inspect 实测确认存在；精确调用细节开发阶段查（cordis-plugin-development skill）。

### UI 布局（2026-08-18 定，槽位已实测确认）

| 位置 | 槽位 | 内容 |
|---|---|---|
| 工具行（高频入口） | `conversation.input.left`（list，已确认） | **记忆按钮**：触发规范记忆流程 |
| 设置页（低频一次性） | `settings.plugin.item`（keyed，key=插件 id，**首个占用者**，已确认） | **记忆设置卡片** |
| 浮层（看记忆） | `shell.overlay`（list，已确认） | **记忆浏览器**：列活跃记忆 + 点开读 |

**设置卡片内容**（client 卡片 + host RPC 执行）：
- 记忆根目录配置（默认 `~/Documents/DSH/memory/`，可改——跨平台配置项）
- **"初始化记忆仓库"按钮**：一键建目录结构（README/staging/common/references/archive + AGENTS.bak）+ `git init`
- git 管理开关（环境有 git 才生效）
- **"浏览记忆"按钮**：打开 `shell.overlay` 记忆浏览器（复用索引 glob 数据列文件名，点开 read 全文）——补齐"随时看/翻旧账"入口
- 状态只读行：活跃索引条目数、staging 池条目数、git 状态（未初始化/干净/待提交）

UI 遵循插件同步规范：dsw token（无硬编码色）、按钮样板、线性 SVG 图标（记忆=卡片+笔风格）、不占多余工具行（只此一个高频入口）。

### 接口映射

| 机制 | 官方接口（已确认） | 用途 |
|---|---|---|
| 开局注入 | `systemPrompt.section()`（官方 prompt 注册点）+ per-agent 状态控制"仅首轮返回索引" | 首轮注入记忆索引 |
| 记忆按钮 | client 槽位 `conversation.input.left` → **往 composer 输入框塞"记忆流程指令"文本**（官方 UI 能力，plan-switch 同款已验证，无 RPC/无会话注入） | 触发规范记忆流程 |
| 浏览记忆 | `shell.overlay`（list）复用索引 glob 数据 → 点开 `read` 全文 | 看/翻旧账入口 |
| 记忆写入工具 | `tools.register()`（ToolDefinition + schema 校验） | 强制格式写入、产出物回执 |
| 写入审批 | `sandboxPolicy`（全局记忆在工作区外 → 写入自动弹审批） | 全局写前确认的天然机械 |
| 会话生命周期 | `agent/session-start` / `agent/created` / `agent/disposed` | 初始化索引缓存 / 清理状态 |
| v2 写入拦截 | `fs/write-intent`（waterfall，writeText 前决策）、`tools/pre-execute`（工具派发前） | 格式乱了的实例出现后启用 |

### 两条链（数据流）

**① 注入链（忆）**：`agent/session-start` → glob 生成索引文本（三段文件名清单）→ `systemPrompt.section` 首轮返回索引、后续轮返回空（per-agent 状态控制）
- 输入内容：项目 memory/ + 项目 docs/ + 全局 common/，按分类前缀分组
- 注入失败容错：索引生成失败 → 静默跳过，下轮重试，不影响会话

**② 写入链（记→存）**：记忆按钮点击 → 输入框塞"记忆流程指令" → 用户发送 → agent 走规范流程（回顾→提议→确认）→ `memory-write` 工具（schema 强制：文件名/位置/≤2KB/日期首行）→ fs 写入（全局目录触发沙箱审批）→ 工具输出产出物回执 → agent 贴出 → git commit（`mem: 记 xxx`）

### 经济性预算（每会话常态）

| 项 | token 成本 | 说明 |
|---|---|---|
| 索引注入 | ~200~500 token，仅首轮一次 | 100 文件内的文件名清单 |
| 记忆流程指令 | ~80 token/次 | 仅按钮触发时（用户主动） |
| 写入回执 | ~100 token/次 | 工具输出 |
| **合计** | **常态 ~200~500 token/会话** | 按钮/写入按用户实际使用另计，可忽略 |

**输出控制**：指令文本固定模板（短句）；索引只列文件名不列内容；工具回执固定格式。**输入控制**：索引永远 ≤ 200 条目；内容按需读全文（≤2KB/文件），不整目录灌入。

### 稳定性设计

- 全部官方接口 + 零运行时依赖；per-session 作用域 + `ctx.effect` 清理
- **无定时器、无后台轮询、无自检钩子**：按钮=塞文本（纯前端 UI 能力，plan-switch 已验证）、注入=section 首轮一次，全是同步、无副作用的官方路径
- 单点故障容错：任一钩子失败 → 静默降级（索引下轮重试），不影响对话主流程
- v1 不拦截（`fs/write-intent`/`tools/pre-execute` 仅 v2 预案）

## 四、讨论中的关键洞察（防止重复踩坑）

- **三类记忆（默认/升级/参考）混了两个维度**：来源（怎么来的）vs 用法（怎么用的）。真正决定放哪的只有：谁在用（全局/项目）× 什么时候要（每次带/按需翻）。
- **路径只解决"找得到"，不解决"想得起"**：AI 知道有 memory/ 目录 ≠ 它会去读。解决"想得起"靠开局注入索引（插件）+ 检索永远现场搜文件。
- **DSH 加载机制只有两个槽位**（全局、项目），没有第三个。任何"中间层"想法都是自造复杂度。
- **AGENTS.md 预算共享**：便利贴保持薄，才不会把项目规则挤掉（64KB 从宽泛端开始砍，全局最先被牺牲）。
- **机械限制只买"入口"的确定性，不买"存储"的完美**：存储层出错全部有容错兜底（glob 全收、检索统一覆盖、冷区可搜、你过目整理），为它们写代码是浪费钱。
- **记忆价值 = 关键时刻捞到它的概率 × 相关性**：开局注入索引提概率，命名规范/判断标准/2KB 上限保相关性。
